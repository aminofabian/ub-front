## Issues found and fixed

### P0 — Cross-host login blocked by CSP

`POST /api/auth/store-session` answered `303` to `{slug}.kiosk.ke`. The
`form-action 'self'` CSP applies to redirects of form navigations, so the browser
blocked the hop and owners could not reach their shop subdomain after login or
signup. Replaced the redirect with a no-store HTML bridge (`location.replace`
plus meta-refresh fallback), preserving the `Set-Cookie` headers on the origin.
Verified with a direct form POST and a real login.

Files: `frontend/app/api/auth/store-session/route.ts`

### P0 — Login on `localhost` looped back to the login page

Bare `localhost` was treated as the platform apex and handed off to
`kiosk.localhost`, but host-only cookies cannot follow that hop. The documented
local workflow (`http://localhost:3000` + `NEXT_PUBLIC_TENANT_ID`) therefore
could not sign in. Bare local hosts now stay on the shop origin.

Files: `frontend/lib/post-auth-navigation.ts`, test added.

### P1 — Tenant owners got `401` from all `/api/v1/admin/**` APIs

Tenant JWTs carry no `GrantedAuthority`; permissions are resolved by
`DataPermissionEvaluator`. The `hasAnyRole("OWNER","ADMIN","SUPER_ADMIN")` rule
rejected every owner. The namespace now requires authentication and relies on
the controllers' existing `hasPermission(...)` checks. Sync-conflicts list/count
verified `200`.

Files: `backend/.../configuration/SecurityConfig.java`

### P1 — VAT report crashed with `500`

The endpoint declared `defaultValue = "day"` but the enum is `DAY`; the UI sent
lowercase. Parameter parsing is now case-insensitive for both the buckets and
CSV endpoints. Verified `200` and CSV output.

Files: `backend/.../finance/api/FinanceReportsController.java`

### P1 — Sync Conflicts showed “no conflicts” while failing

On API failure the page rendered both the error banner and the green “No pending
sync conflicts” state. The empty state is now suppressed when an error exists.

Files: `frontend/app/(dashboard)/sync-conflicts/page.tsx`

### P1 — Invalid inline `<script>` in client catalog/stock components

React logged “Encountered a script tag while rendering React component…” and the
pre-paint column-width restore never ran on client navigation. Removed the
invalid tags; the existing `useColumnWidths` hook restores widths after mount.

Files: `frontend/app/(dashboard)/products/_components/VirtualizedCatalogBody.tsx`
(the same pattern in the stock sheet was already removed in the working tree).

### P1 — Duplicate `#catalog-omni` IDs broke the `/` search shortcut on mobile

Desktop and mobile search inputs shared one ID; the shortcut always focused the
hidden desktop field. IDs are now unique, both carry `data-catalog-omni`, and
the shortcut focuses the first visible field.

Files: `ProductFilterSidebar.tsx`, `ProductMobileChrome.tsx`,
`useCatalogList.ts`

### P2 — Business-settings drawer fields clipped

Inside the narrow theatre drawer the form still used `sm:grid-cols-2` and
`sm:col-span-2`, creating implicit columns; selects and labels were clipped.
The profile/storefront grids now stack in the theatre layout.

Files: `frontend/components/business/business-settings-form.tsx`

### P2 — Email campaign preview fired an avoidable `400`

Opening “New email” called `audience-preview` with an empty hand-picked list and
displayed “Select at least one customer” as an error. The preview is skipped
until at least one customer is selected.

Files: `frontend/components/credits/customer-email-campaign-composer.tsx`

### P2 — TypeScript error in Google shop pick

`session` was widened to `{ businessId?: unknown }`; typed as
`AuthSessionClaims`. `tsc --noEmit` now exits 0.

Files: `frontend/lib/google-shop-pick.ts`

## Unresolved / limitations

1. **Anonymous `/api/auth/restore-session` 401 console noise** on public pages
   (`/shop`, `/privacy`, `/marketplace`, …). No functional impact; the UI falls
   back to anonymous. A guard in `restoreClientSessionFromCookie` would silence
   it but risks Safari session restore, so it was left for a targeted fix.
2. **Dashboard tab titles** are the tenant storefront title on most pages
   (only ~38 routes export metadata). Needs a document-title strategy across the
   dashboard layout.
3. **Storefront data quality:** the seeded tenant exposes 30+ “IMPORTED
   CATEGORY” rows and several 0-item categories. The UI displays them; hiding
   zero-item categories and cleaning seed data would improve the shop.
4. **Expected no-data 404s** appear in the console: “No open shift”, “No daily
   audit”, “No restock manifest”, “Till device not registered”. The UI handles
   each with an empty state; returning `200` with a null body would remove the
   noise.
5. **Not testable in this environment:** Google OAuth (not configured), staff
   signup token, email/SMS delivery, live M-Pesa STK/card payments, drawout
   approval links (token required), supplier-portal authenticated pages (no
   supplier credentials), super-admin console (no platform-admin credentials).
6. **Checkout completion** stopped at the shopper sign-in gate; placing the
   order requires a shopper account/OTP. Cart, delivery, and contact validation
   were verified up to that gate.
7. **Local test data changed:** owner password set to `QaPass123!`, till PIN
   `4729`, and a till named “QA Front Counter” registered for Mirema Drive in
   the local `ub` database. Restore/reseed the local DB if those changes matter.
